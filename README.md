## 한눈에 보기

- **타겟 사용자**: IT/개발 직군 취업·이직을 준비하며 기업을 분석하는 사람
- **입력 / 출력**: 기사 제목·매체/날짜·본문 → 기업/이슈 1줄 + 3줄 요약 + 직무 연관성(근거, 추론 표시) + 확인 필요
- **선정 모델**: Claude Sonnet 5.5 (사실 오류 없음, 추론을 전부 표시). 무료로 쓸 수 있는 모델은 Gemini, GPT-6
- **적용 기법**: Few-shot 3건(되묻기 1건 포함). 단계적 추론 유도는 쓰지 않음
- **검증 결과**: 환각 검증 질문 10건 중 9건 Pass, 1건 Fail(거짓 전제 질문 → v2에서 수정)

## 평가 질문별 설명 포인트

### 1. 기능 동작 검증

- 과업은 [system-design 1번](docs/system-design.md)에 정의했다. 타겟 사용자, 입력, 출력 규격이 같이 있다.
- 입력 템플릿은 3-3에 있고, 코드 블록이라 그대로 복사해 쓸 수 있다.
- 모델 비교는 기준 4개(형식 준수, 사실 정확성, 직무 연관성의 근거성, 지어내지 않기)에 1~5점과 근거를 적은 표다.
- Few-shot은 3건이고, 예시 3이 모호한 입력에 되묻는 흐름이다.
- 환각 검증 질문 10건에 Pass/Fail 판정을 적었다.
- 대화 로그는 26턴이고, 턴 13에서 조건을 바꿨다(직무 연관성을 백엔드 중심으로).
- 미해결 기록은 2건이고, 각각 시도한 프롬프트와 막힌 이유가 있다.

### 2. 동작 구조 설계

- **프롬프트를 나눈 이유**: 시스템 프롬프트는 역할과 규칙(항상 적용), 유저 프롬프트는 이번 기사와 요청(실제 사용), 입력 템플릿은 빈칸만 바꿔 재사용하는 틀이다. 나누면 규칙은 고정하고 입력만 바꿀 수 있고, 어디를 고쳐야 할지 알기 쉽다.
- **v1→v2**: 환각 검증 10번(거짓 전제)에서 AI가 기사에 없는 "제어 소프트웨어 개발" 역할을 지어냈다. 그래서 [요청]에 6번(질문에 기사에 없는 전제가 있으면 먼저 바로잡기)과 7번(확인 불가일 때 확인 방법 한 줄)을 추가했다.
- **점수 근거**: 기사 원문과 직접 대조했다. 예를 들어 GPT-6는 오류 2건(아틀라스를 오토에버 사업처럼 씀, 전망을 사실처럼 씀)이라 사실 정확성 3점이다.

### 3. 핵심 기술 원리 적용

- **환각**: 기사에 없거나 기사와 다른 내용을 사실처럼 말하는 것. 창의적 생성과 달리 정답이 기사 안에 있어서 틀렸는지 확인할 수 있다. LLM은 확률로 다음 문장을 만들기 때문에 모르는 부분도 그럴듯하게 채울 수 있다.
- **Pass 기준**: A는 정답과 근거를 같이 낸 것, B는 모른다고 밝힌 것. 둘 다 아니면 Fail. 10번은 거짓 전제를 받아들여 없는 역할을 지어냈으므로 Fail이다.
- **모델 선정 이유**: 이 과업은 사실을 단정하지 않는 것이 가장 중요하다. 형식은 프롬프트로 고칠 수 있지만 사실 단정은 고치기 어려워서, 오류가 없고 추론을 전부 표시한 Claude를 골랐다.
- **기법 선택**: Zero-shot은 한 줄이 두 문장이 되고 "(추론)"을 빼먹었다. Few-shot을 넣자 형식과 표시가 안정됐다. 단계적 추론 유도는 기사에 없는 내용을 추론해서 덧붙일 위험이 있어 쓰지 않았다.
- **페르소나**: 말투는 짧고 사실만 적는 합니다체, 금지 사항은 기사에 없는 수치·날짜·기업명·인물·원인을 만들지 않는 것, 우선순위는 사실 정확성 > 근거 > 형식. 업무 문제(지어내기, 근거 없는 단정)에서 바로 나온 규칙이다.

### 4. 심층 인터뷰 (예상 답변)

- **무료 모델만 쓴다면**: Few-shot 예시를 늘리고, "(추론)" 표시와 "기사에서 확인 불가" 규칙을 요청마다 반복해서 넣는다. 결과는 검증 질문(정답 아는 질문)으로 한 번 더 확인하고, 사람이 마지막으로 원문과 대조한다.
- **정책·수치가 자주 바뀐다면**: 모델 기억에 맡기지 않고 최신 원문을 매번 입력으로 넣는다. "입력 자료에 없는 것은 확인 불가"로 답하게 하고, 원문 날짜를 같이 적게 한다. 검증 질문 세트를 정기적으로 다시 돌린다.
- **10턴 이상에서 문맥이 끊긴다면**: 중요한 조건(예: 백엔드 중심)을 시스템 프롬프트로 올려 고정하고, 일정 턴마다 조건을 다시 알려 주거나 새 대화에 요약해서 이어 간다. 이번 로그에서는 문맥 끊김이 나타나지 않았다.
- **작업 기록 단위**: 한 항목에 작업 하나(과업 정의, 모델 선정, v2 작성처럼)만 적었다. 읽는 사람이 무엇을 했는지 알 수 있고, 어디서 막혔는지 따로 짚을 수 있기 때문이다.

## 미해결 과업 (요약)

1. 기사 URL만 주면 모델이 기사를 열지 못해도 제목만 보고 지어서 요약함. 본문을 붙여 넣는 방식으로 우회함.
2. "(추론)" 표시를 가끔 빠뜨리고, 같은 입력에도 결과가 달라짐. 사람의 마지막 확인이 필요함.
